# AI Mentor Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A VR mock-interview mentor: a Meta Quest interviewer that asks real reported questions for a Calgary company and role, scores each answer and coaches you, plus a web app and iOS app with a career roadmap map and an anonymous, agent-fed interview memory.

**Architecture:** Serverless on Cloudflare. One TypeScript Worker (Hono) serves the API and the built React app as static assets, so web, Quest and API share one HTTPS origin. D1 holds relational data, Vectorize holds embeddings (Workers AI `@cf/baai/bge-base-en-v1.5`, 768 dims), a Cron Trigger runs the research agent. Clients talk to Gemini Live directly with a short-lived token minted by the Worker, so no Gemini key ever reaches a client. Pure logic lives in `shared/` and is imported by both the Worker and the web app.

**Tech Stack:** TypeScript everywhere except iOS. pnpm workspaces. Server: Cloudflare Workers + Hono, D1, Vectorize, Workers AI, Cron Triggers, wrangler. Web: Vite + React, @react-three/fiber + @react-three/xr + @react-three/drei, @xyflow/react. Tests: Vitest, `@cloudflare/vitest-pool-workers` for Worker + D1 tests. AI: Gemini API (Live API voice, generateContent with structured output and Google Search grounding). iOS: SwiftUI, Swift 6, URLSession + Codable, Swift Testing.

**Spec:** `docs/superpowers/specs/2026-11-07-ai-mentor-design.md`

## Global Constraints

- Deadline: Devpost submission 11:30 AM ABT Sunday Nov 8. Everything committed and pushed by 10:30 AM.
- All code written during the event. Every AI-assisted piece logged in `docs/ai-usage.md`.
- No Gemini key in any client (web bundle, Quest, iOS). It lives only as a Worker secret (`wrangler secret put GEMINI_API_KEY`). Clients hold only an anonymous session token and an ephemeral Gemini token.
- Research agent: public pages only, obey robots.txt, no login-walled sites (Glassdoor, LinkedIn, Indeed), no bot-check evasion. Every stored fact has `source_url` and `fetched_at`.
- Seeded memory rows carry `is_seeded = 1` and the UI labels them "example". Never shown as real reports.
- A company's reported questions are only returned when at least 3 reports exist for that company (k = 3). No endpoint returns raw `experiences` rows.
- Labour data shown must come from the real sources (Job Bank, StatCan, Alberta outlook, Adzuna). No invented numbers.
- VR target: Meta Quest 3, Meta Quest Browser, WebXR `immersive-vr`, over HTTPS (the workers.dev URL). Same scene must render in a desktop browser without XR.
- Code style: few comments (only the non-obvious why), no boilerplate docstrings. Commit messages imperative, under 50 chars, no AI attribution.
- Accessibility: keyboard reachable, visible focus, captions of interviewer speech on screen and in VR, respects `prefers-reduced-motion`.

## Review Focus

- Mic permission denied or no mic → clear message and a text-answer fallback, not a frozen scene. (Task 6 test)
- Gemini Live socket drops mid-interview → "reconnecting", transcript and scores kept, resumes on the current question. (Task 6 test)
- Submitted experience contains the author's name, email or phone → stored text has them removed. (Task 3 test)
- Company with fewer than 3 reports → insights return facts but no questions; interviewer falls back to role-generic questions. (Task 2 and Task 5 tests)
- robots.txt disallow or 403 on a source → URL skipped, nothing stored, never retried under another identity. (Task 4 test)

### Task 4: Research agent

**Files:**
- Create: `shared/src/robots.ts`, `shared/test/robots.test.ts`, `server/src/research.ts`, `server/test/research.test.ts`

**Interfaces:**
- `isAllowed(robotsTxt: string, userAgent: string, path: string): boolean`: longest-match Allow/Disallow in the group for `userAgent`, else `*`.
- `BLOCKED_HOSTS = ['glassdoor.com', 'glassdoor.ca', 'linkedin.com', 'indeed.com']`, `isBlockedHost(url: string): boolean`.
- The agent is a Gemini function-calling loop (`server/src/agent/`) with a tool registry, max 12 steps per run. Tools:
  - `web_search({ query })`: Keenable `POST https://api.keenable.ai/v1/search` (`X-API-Key: KEENABLE_API_KEY`); results from blocked hosts are dropped.
  - `fetch_page({ url })`: refuses blocked hosts and robots.txt disallows (checked with `isAllowed`), then Keenable `POST /v1/fetch`; returns trimmed text.
  - `memory_search({ company, query })`: Vectorize query over `fact:` and `exp:` vectors filtered by company, hydrated from D1.
  - `save_fact({ company, kind, text, source_url })`: rejects a missing or blocked `source_url`; inserts with `content_hash = sha256(kind + text)` (duplicates ignored) and upserts vector `fact:<id>`.
- `researchCompany(env, slug: string): Promise<{ added: number; skipped: string[] }>`: runs the agent with the goal "find current hiring, interview-process, tech and news facts about <company> in Calgary, check memory first, save only new facts with sources", then sets `last_researched_at`.
- `GET /api/memory/:slug?q=` (session): `memory_search` for clients (facts only, plus questions when k ≥ 3).
- Routes: `POST /api/research/:slug` (requires session, max once per company per 30 min). The `scheduled()` handler researches every `tracked = 1` company.
